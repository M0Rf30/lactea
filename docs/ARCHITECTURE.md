# lactea architecture and fidelity contract

lactea is a pure-Rust MilkDrop 2/3 and projectM-compatible visualizer: a library that renders
into any host-provided wgpu texture, plus a standalone app. Fidelity is **measured**, never
eyeballed: every layer has an oracle and a numeric gate from day 0.

Embedding rule: library crates never create windows, surfaces, threads or audio devices and
never touch the filesystem (presets/textures come in as bytes), so they also build for wasm. The
filesystem, GPU-device and decode work lives in `lactea-host`, which only the native hosts
(app, C API, `fdrender`) use.

## Determinism contract (oracle and lactea are driven identically)

- `RunConfig` defaults: 640×360, mesh 48×36, 60 fps, seed 1, texel offset (0, 0).
- Frame `n` time is exactly `n / fps`; projectM is driven with `projectm_set_frame_time`.
- Before frame `n`, push PCM sample frames `abi::pcm_range(n, sr, fps)`.
- Audio fixtures: `fixtures/audio/*.wav` generated by `fixtures/audio/gen_audio.py` (stdlib only).
- Every RNG (rand_frame, rand_preset, rot_rand, noise textures, eel `rand`) is seeded from the run seed.
- Texel offset: MD2 adds 0.5 texel to cancel D3D9 pixel-centre rules; on Vulkan/Metal/DX12/GL the
  net-equivalent is 0 — copying the constant produces a steady drift.
- Internal images are `Rgba8Unorm`: 8-bit feedback quantisation is part of the MilkDrop look.
  Never render in sRGB space; if the host target is sRGB, the final pass compensates.

## Dump layout (see `lactea_abi::dump`)

```
<dir>/meta.json                DumpMeta { producer, preset, audio, config: RunConfig, stages, has_vars }
<dir>/<stage>/<frame:05>.png   stage ∈ final | main | warped | blur1 | blur2 | blur3 ; RGBA8, row 0 = top
<dir>/vars/<frame:05>.json     per-frame vars after per-frame eqs, lowercase, + rand_frame.x.. rand_preset.x..
<dir>/textures/<name>.png      static textures (noise_*), 3D volumes as .bin
```

`main` is the image the next frame's warp samples; `warped` is the image right after the warp
pass. Blur levels are computed after the warp pass but from the *previous* frame's `main`
(`BlurPasses` samples `m_lpVS[0]`; buffers swap after the composite) — MD2's own comment
("blurs the current frame after warp") is stale. Motion vectors are drawn onto the previous
image before the warp.

Where projectM and MD2 differ, lactea defaults to projectM (the measurement oracle) and keeps
the MD2 behaviour behind `Compat::MilkDrop2` (`Compat::MilkDrop3` adds the MD3 deltas on top, `docs/md3.md`); every case is listed in `docs/divergences.md`.

## Fidelity ladder (each rung isolates one source of error)

1. **Expression**: corpus code + random programs, lactea-eel vs projectm-eval, bitwise f64.
2. **Shader semantics**: every corpus warp/comp shader, our WGSL vs glslang SPIR-V of the same
   MD2-wrapped HLSL, on fixed synthetic inputs; max abs diff ≤ 2/255.
3. **Single step (teacher forcing)**: load oracle frame `n-1` `main` (+ oracle vars) into
   lactea, render frame `n`, diff each stage. Errors cannot accumulate, so each diff points
   at one pass (warp vs blur vs shapes/waves vs comp).
4. **Free run**: N frames from identical inputs; per-frame PSNR/SSIM curves, first diverging
   frame, contact sheets / side-by-side video for human review.
5. **Corpus gate**: per-preset status (parse / eel / hlsl / L3 / L4); scores must never regress.

Known oracle deviations (projectM ≠ MD2) go into `docs/divergences.md` with MD2 source
references. Current numbers: `docs/fidelity.md`.
