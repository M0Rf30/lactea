# Contributing to Lactea

Thanks for helping. Bug reports and feature requests go through the issue templates; for code,
open a pull request against `main`.

## Commits and pull requests

Commits and PR titles follow [Conventional Commits](https://www.conventionalcommits.org/):
`type(scope): summary`, with `type` one of `feat`, `fix`, `perf`, `refactor`, `docs`, `test`,
`build`, `ci`, `chore`, `revert` and `scope` usually a crate (`render`, `hlsl`, `eel`, `app`, ...).
Mark breaking changes with `!` or a `BREAKING CHANGE:` footer. CI lints the PR title and every
commit; PRs are squash-merged, so the title becomes the changelog line. `CHANGELOG.md` and version
bumps are generated by release-plz from these messages; do not edit them by hand.

## Building and testing

```sh
cargo fmt --all
cargo clippy --workspace --all-targets --exclude lactea-app --exclude lactea-eel-oracle -- -D warnings -A clippy::approx_constant
python3 fixtures/audio/gen_audio.py              # test audio, stdlib only
cargo test --workspace --exclude lactea-app
cargo check -p lactea-app --no-default-features --features engine
```

Tests that need a GPU, the projectM preset collection or the reference build skip themselves with a
message when the resource is missing. Linux build dependencies are listed in the README.

Memory tips: linking wgpu is heavy. On a small machine use `CARGO_BUILD_JOBS=2`, give each git
worktree its own `CARGO_TARGET_DIR`, and run one render loop at a time.

## Rendering changes and the fidelity loop

The rules for rendering code (projectM is the reference, port rather than approximate, the ABI
crate is frozen, determinism) are in [`AGENTS.md`](AGENTS.md); the method and numbers are in
[`docs/fidelity.md`](docs/fidelity.md). The reference build and the loop (`oracle/build.sh`,
`scripts/fidelity.sh`) are **optional** for contributors: run them when your change is meant to
alter rendering and attach the before/after numbers to the PR. Refactors and non-rendering changes
are verified by tests and clippy alone.

## Library code

No panics on caller input (return errors), no per-frame allocations in hot paths where a reused
buffer works, public items documented (`#![warn(missing_docs)]`), internals `pub(crate)`.
Comments explain why or state an invariant.
